# Pull request review and integration decisions

## Integration decisions after review

The owner authorized accepting the in-scope PRs and closing the others. The
integration branch preserves the original commits from **#8, #9, #10, #11,
#14, #16, #17, #19, #20, #21, and #22**. Merge commits resolve conflicts and
apply the compatibility and safety corrections described below. A merge commit
into `main` preserves that ancestry so GitHub can mark these original PRs merged.

- Portable storage requires an explicit `rivet-portable` marker. Installed
  copies retain their existing profile. Portable profiles also have separate
  instance routing and keep logs with their data; migration remains explicit.
- Font and line-number commands use distinct IDs from spellcheck. Font selection
  exposes supported settings and releases application-state borrows before its
  modal message loop.
- Auto save extensions preserve existing alternate and unknown extensions.
- Deleted files are handled at the metadata operation; other errors still surface.
- Temporary narrow-window layouts no longer overwrite the preferred tab width.
- Only the standalone main-window DPI handler from #25 is adapted. Its original
  branch also contains #23's rejected toolbar, so #25 is closed without merging
  that branch.

Close **#13, #18, #23, and #24** as declined design/features, and **#15** as already
covered by v0.4.25. Close **#12** because the current 35-entry accelerator table
passes 100 creation/destruction cycles in an optimized build. CI retains that
regression check.

Local validation of the integrated v0.4.26 code passed formatting, all-target
Clippy with warnings denied, a release build, dependency audit, 148 regular tests,
and 14 native Windows tests. The latter include dialog background painting and
control geometry, font/line-number persistence, save history, deleted files,
and suggested DPI bounds. These tests do not establish visual correctness on
physical mixed-DPI monitors or replace interactive font-picker testing.

## Integration hazards in the larger PRs

1. **Portable detection (#8):** The
   [proposed probe](https://github.com/mgelsinger/rivetnotes/blob/1e23686de3edeec4aa23768db9a16a0ea6b517a4/src/app/session.rs#L208)
   prefers an executable-adjacent `data` directory whenever writable. Our
   per-user installer also installs to a writable directory. Applying this
   unchanged would switch that installation away from existing AppData sessions
   and settings without migrating them, making notes appear missing. Use an
   explicit portable marker or option and account for existing state.
2. **Font command collision (#17):** Its
   [IDM_VIEW_FONT = 357](https://github.com/mgelsinger/rivetnotes/blob/7df419d160da6eb2b1d494234d6402cdd91f81bb/src/platform/win32.rs#L154)
   collides with current `IDM_VIEW_SPELLCHECK = 357`. Assign a distinct command ID.
   The font dialog also enables effect controls while retaining only family and
   size, so exposed controls should match supported settings.
3. **Help menu and font lifetime (#23):** The PR removes the window's native
   menu and creates only
   [three toolbar labels](https://github.com/mgelsinger/rivetnotes/blob/0cd2d995b2dbe484d174ed43f6ee24afed435bf0/src/platform/win32.rs#L1083).
   Adapting that unchanged would leave the current Help/update commands without
   a menu entry point. Preserve Help, keyboard navigation, and accessibility.
   Its single-entry font cache overwrites the old handle when DPI changes
   without freeing it or retaining it for reuse. The startup-checkmark rationale
   in the description also needs rechecking: current menu helpers use `GetMenu`
   directly and receive the state from their caller.
4. **Printing (#24):**
   [draw_print_band](https://github.com/mgelsinger/rivetnotes/blob/2907cf7891f5ced860cf1b495198e700cf28584c/src/platform/win32.rs#L3542)
   creates a font for each header and footer, restores the previous font, but
   never deletes the new one. Print-dialog allocations also lack cleanup, and
   `StartPage`, `EndPage`, and `EndDoc` results are ignored. These need structured
   cleanup and error handling, including failed or cancelled jobs. The PR's
   documentation refers to #22's line-number toggle, which it does not include.

## Recommended order

1. Close #15 as superseded.
2. Address #11, #14, #16, and #20 with targeted regression coverage and dialog QA.
3. Consolidate #10/#19/#21 into one save-dialog and extension improvement.
4. Consider #9, #17, and #22 as separate convenience features. Reproduce #12's
   reported 35-entry release-build issue when expanding shortcuts.
5. Decide whether timestamp names, a wider default tab strip, portable state,
   printing, and a custom toolbar fit the product. Rework their implementations
   before taking them; keep #25 attached to the toolbar decision while checking
   general DPI behavior separately.

During the original review, no PR was merged, closed, or commented on, and no
application source was changed. Subsequent integration decisions are above.
The review inspected every proposed diff and relevant current code, checked
commit dependencies, simulated merges, and reran the dirty-tab regression test.
It did not build all PR branches or perform fresh printer, mixed-DPI, or visual
theme tests. This limits implementation approval, not the identified source
coverage gaps.
